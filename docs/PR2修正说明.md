# PR #2 修正及验证说明

本页记录 v15 阶段的修正。后续 v16 已增加精确版本的新宿主配置，最新范围及验收状态见 [Build26300 验证与验收](Build26300验证与验收.md)。

## 修改内容

- 继续按 SystemTray.dll、Taskbar.View.dll 的顺序寻找候选宿主，但先做只读探测；不支持的候选不会阻止检查下一个。
- 仅接受已验证的模块身份、导入槽及完整调用点集合。未知布局、额外或缺失调用点、重复目标导入、无效名字表及超限扫描都拒绝启用，不在探测时写入 IAT。
- 原函数入口在发布挂钩前就绪；禁止链接旧版或第三方挂钩。槽更新使用比较交换，失败尝试回滚；回滚或页保护恢复失败时保持透传并拒绝重试，不清空可能仍在被调用的原函数指针。
- 旧版刷新只允许返回地址 0x34C0C 消费加速标志；0x34CB7、0x34D94 仍原样调用系统接口。
- 版本、控制协议及 DLL 文件名同步为 v15，错误状态保留实际安装失败原因。

## 已执行验证

环境为 Windows Build 22631；本机 Taskbar.View.dll 文件版本 623.27903.70.0，PE 时间戳 0x654E6445，映像大小 0x758000。

```bat
tests\run_tests.bat
build.bat artifacts\pr2-v15
```

10 项核心原生测试及 1 项控制器诊断测试通过，实际 DLL、控制器编译成功。新增故障测试在修正前复现过第三方挂钩误接纳、名字读取越界、回滚后原函数被清空、回滚不全仍可重试、返回地址高位截断等问题，修正后通过。候选回退测试调用与生产控制线程相同的选择函数。

独立审查发现控制器会在读取到不支持状态后直接返回退出码 3，跳过错误打印。主代理修正了提示和映射释放；控制器测试让真实命令分支连接本测试进程自己的共享内存，确认失败时输出状态及原因。恢复旧行为后该测试失败，修正后通过，不连接真实任务栏。

真实文件测试只在独立测试进程映射本机系统 DLL，不执行其初始化或其他代码；填入系统导入地址后，生产探测函数核对真实模块身份和全部调用点。该检查证明静态布局符合配置，不能替代真实任务栏显示验收。

## 尚未执行的验收与限制

- 未向真实 Explorer 注入，未改变系统时区，未启动自启守护或重启 Explorer。
- 未实测新旧系统任务栏的启停刷新、多屏、睡眠恢复、跨日及夏令时边界。
- 当前没有 Build 26300 的 SystemTray.dll 语义配置，新宿主会明确拒绝启用。需要逐个调用点的用途证据和隔离测试环境，不能凭 7/7 数量放行。
- 旧版已注入时，即使关闭也保留其 IAT 透传挂钩；新版本拒绝叠加。用户需保存工作后自行重新登录或重启 Explorer，再运行匹配版本的控制器和 DLL。

本修正没有合并或推送 PR，不代表新版 Windows 的兼容性已经完成验收。
