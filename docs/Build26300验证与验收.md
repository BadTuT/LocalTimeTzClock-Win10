# Build 26300 支持、来源及验收

## 当前精确范围

本次基于实际取得的 x64 `SystemTray.dll 2609.11000.100.0` 增加适配；Winbindex Insider 索引将它关联到 Build 26300.9807、26300.9818。模块身份是支持边界，不能据此推断所有 26300+ 都兼容。

PR 作者报告的 `2609.12001.100.0` 没有可核验的相同二进制，**不在本配置范围内**。如果实际电脑属于该版本，应先采集证据，不能只因调用数同为 7/7 就放行。

## 为什么新版只改主时钟取时入口

新模块有两个时钟模型：`ClockSystemTrayIconDataModel` 和 `ClockSystemTrayIconDataModel2`。两者都把主时钟刷新与定时调度分开。

| 路径 | 模型 2 | 模型 1 | 处理 |
|---|---|---|---|
| `RefreshIcon` 的本地时间返回地址 | `0xCA3BD` | `0x12B73D` | 启用时换为目标时区当前时间，保持真实秒数 |
| `ScheduleNextUpdate` 的本地时间返回地址 | `0xCAA7D` | `0x12BCED` | 保持系统时间，仅在请求刷新时把秒改成 59，一次消费 |

模型 2 中，`RefreshIcon` 先在 `0xCA3A7` 调用调度，再在 `0xCA3B7` 取得本地时间，写入局部 `SYSTEMTIME`；同一局部值随后在 `0xCA417` 传给 `UpdateDateString`，在 `0xCA42A` 传给 `GetTimeString`。`0xCA3C8` 单独取得的 UTC 存在另一局部变量，不替换。模型 1 对应的调用链在 `0x12B727`、`0x12B737`、`0x12B797`、`0x12B7AA`，UTC 调用位于 `0x12B748`。

提示函数还会读取附加时钟配置，在 `0xC9227` 经 `SystemTimeToTzSpecificLocalTimeEx` 把独立 UTC 转成附加时区，再通过 `0xC92BE` 等位置调用同一个 `GetTimeString`。因此，按格式化 API 的返回地址全量替换会覆盖附加时钟，不能采用。

新版只修改 `GetLocalTime` 的单个 IAT 槽，并区分以上四个返回点；日期和时间格式化 IAT 都保持不变。旧模块仍使用 v15 已验证的格式化策略，不能把新版数据源策略自动套到旧模块。

## 本次已执行的验证

- 15 项核心原生回归测试：包括真实新旧 DLL 只读映像探测、精确配置匹配与拒绝、IAT 写入范围、主数据源/调度点的真实 x64 调用、停用透传、附加时钟格式化和故障回滚。
- 1 项控制器诊断测试：独立进程连接自身共享内存，验证不支持时输出状态和原因，不向真实 Explorer 注入。
- 1 项确定性跨午夜测试：UTC 固定在 `2026-11-02 16:00:00.005`，旧本地样本为 `23:59:59.990`。修正前曾得到次日 `00:00:59.990`，修正后与目标完整样本 `00:00:00.005` 一致。
- 3 项 Python 采集工具测试：正确记录身份、导入、调用点和 PDB，不修改输入；拒绝非 PE 输入；有效无导入映像仍能采集。
- 采集脚本在本机 Build 22631.2861 的普通模式和 `-IncludeModules` 模式均执行成功；DLL 和控制器已通过 MSVC 编译，产物位于 `artifacts\pr2-v16`，v15 保留。

```bat
tests\run_tests.bat
python -B -m unittest discover -s tools\tests -v
build.bat artifacts\pr2-v16
```

测试从真实文件读取证据，执行挂钩行为时仅运行自建内存映像和测试代码。这些结果不等于已在 Build 26300 桌面运行。

## 只读采集实际电脑证据

在仓库根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\collect_clock_host.ps1
```

脚本在 `artifacts` 下建立新报告目录，记录系统 Build、时区、已加载的时钟模块、文件版本和哈希。有 Python 时还会采集导入、调用点、函数范围和 PDB 标识；没有 Python 时会明确记录缺少深度证据。

如需同时保存原始 DLL，显式添加 `-IncludeModules`。该选项只复制系统文件到报告目录，不执行文件。脚本不会调用 `on/off/watch/install`，不会改变时区、注册表或重启 Explorer。

也可以只分析一个已取得的文件：

```powershell
python -B .\tools\clock_host_evidence.py "路径\SystemTray.dll" --out module-evidence.json
```

调用点逐字节扫描提供位置证据，不能自动证明用途，不能替代符号、反汇编和真实界面检查。

## 真机验收：当前尚未执行

下列步骤应在受控的 Build 26300 测试电脑完成。建议用单独的测试目录，不覆盖正在使用的安装目录。

1. 先运行采集脚本，确认模块版本、时间戳、映像大小和哈希与本次证据匹配；不匹配时停止，提供新证据，不放宽检查。
2. 如果旧版已注入，保存工作后自行重新登录或通过任务管理器重启 Explorer。旧版的 `off` 仅透传，并不卸载 DLL，新版不会叠加挂钩。
3. 将 `artifacts\pr2-v16` 中的 `tzclock.exe`、`tzclock_v16.dll`、`tzclock.ini` 成套复制到测试目录。配置目标时区，测试时可临时启用 `Log=1`，保留已有配置备份。
4. 执行以下命令，记录输出和实际任务栏画面：

```powershell
$beforeZone = (Get-TimeZone).Id
.\tzclock.exe on
.\tzclock.exe status
[TimeZoneInfo]::ConvertTimeBySystemTimeZoneId([DateTime]::UtcNow, 'China Standard Time')
.\tzclock.exe off
.\tzclock.exe status
if ((Get-TimeZone).Id -ne $beforeZone) { throw '系统时区发生变化，验收失败' }
```

参考命令里的时区名应与测试配置一致。先选择与系统当前偏移不同的目标时区，避免两者恰好相同而无法观察切换。运行成功码和计数增加只能说明进入挂钩，不能代替肉眼核对时间、日期和恢复行为。

| 验收项 | 通过条件 | 状态 |
|---|---|---|
| 主时钟与日期 | 时间、日期、秒数符合目标时区，跨日一致 | 待真机 |
| 启用与停用 | 无须自动重启 Explorer 即可切换并恢复，未伪造显示秒数 | 待真机 |
| 附加时钟与悬停提示 | 原生附加时钟保持自己配置的时区，主时钟信息无混乱 | 待真机 |
| 系统与其他程序 | 系统时区和系统时间未改，其他程序仍按系统时区 | 待真机 |
| 多屏和显示秒数开关 | 主副任务栏一致，启停无残留 | 待真机 |
| 睡眠和显示器关闭后恢复 | 时钟恢复正常，未卡住或污染秒数 | 待真机 |
| Explorer 重新启动 | 手动重新启用后恢复，控制器和 DLL 版本相同 | 待真机 |

点击时钟打开的日历面板仍由系统时区驱动，本次不修改该进程或面板。测试结束后关闭工具、恢复测试配置；不自动写入登录自启。
